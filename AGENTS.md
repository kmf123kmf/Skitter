# Agent notes

## Environment
- Python 3.11–3.14 only (faiss-cpu lacks 3.15 wheels). The venv is `.venv` (Python 3.11).
- PowerShell: run tools from the venv directly, e.g. `.venv\Scripts\python.exe -m pytest -q`.

## Verify
- `.venv\Scripts\python.exe -m pytest -q -n 8` (headless; Qt runs offscreen; in parallel with pytest-xdist, about 35 s; about 85 s without `-n`). Tests run in separate worker processes, so each must set up its own state (no reliance on test order).
- `.venv\Scripts\ruff.exe check .` and `.venv\Scripts\ruff.exe format --check .`
- Matching at scale: `.venv\Scripts\python.exe scripts\bench_matching.py`

## Conventions
- `skitter.core` must not import Qt. Long core operations take `progress`/`cancelled` callbacks; the UI runs them via `Session` + `ui/jobs.Job`.
- Settings are declared with `Param`s on a `Configurable` (`core/slicing/params.py`); `ParamForm` builds their UI. A setting that applies only sometimes has `when` (the form hides it otherwise); one that depends on another sets `under="that_one"` and is declared right after it (shown indented; `test_settings_sit_right_below_the_one_they_belong_with` checks every registered class). Long lists are split by declaring `Section("Title")` markers (foldable headings; an untitled `Section()` ends them, e.g. before Seed).
- Slicing runs in the background: operations take `apply(regions, ctx, progress)` / `subdivide(region, ctx, progress)` and should call `progress(fraction)` at natural points in slow work (it also cancels). Tests slice inline by default (`tests/conftest.py`); use the `background_slicing` fixture to test the worker thread.
- A slicing plan (`core/slicing/plan.py`) is one slicer (a registered operation) and, optionally, its cells split by detail (the quadtree, not a slicer of its own); the plan keeps every slicer's settings. Older files' stage lists are converted in `SlicingPlan.from_dict`.
- New slicers: lattice patterns go through `slicing/frame.PinnedFrame` (anchor + rotation for free); shared settings (anchor, rotation, orientation, seed) come from `slicing/common.py`; size tiles with `ctx.tile_dims(scale)`.
- numba kernels use `cache=True, nogil=True` (so background jobs don't block the UI thread).
- An error raised in a Qt slot fails the test (`tests/conftest.py`'s autouse `slot_errors`: Qt only prints them). A test that expects one requests `slot_errors` and empties the list after checking it. Steps with background work of their own stop it in `shutdown()`, which the test `window` fixture calls as closing the window does.
- Tests must never touch the real tile library: `tests/conftest.py` points `LOCALAPPDATA` at a temp dir; open libraries in `tmp_path`.
- UI preferences go through `ui/preferences.settings()` (INI); `tests/conftest.py` redirects its path.
- Build actions with `ui/actions.make_action` (its tooltip names its shortcut) and show them with `tool_button`; muted/warning text, progress bars and byte sizes come from `ui/style.py`. The export windows share `ui/export_window.ExportWindow`.
- Side panels (`steps/base.side_panel`) never scroll sideways, so their content must fit the panel's width (320 px of content; `resizable` panels start there and can be dragged wider, see `view_and_panel`). Let long or changing text wrap (`setWordWrap(True)`), especially beside a button on one row; clip long paths (`fixed_width`). `test_every_side_panel_fits_its_width` checks every tab with the Windows UI font (offscreen Qt measures text far wider): when a panel gains a state that shows new widgets, add that state to the test.
- Mosaic units: the canvas is always `CANVAS_WIDTH` (4000) across, whatever the layout; a base tile is `layout.tile_width` (`CANVAS_WIDTH / columns`). Store positions in mosaic units (they stay put on the picture when the layout changes) and sizes relative to the tile or the canvas; never assume a tile is 100 units.
- Project state is saved in `.skitter` files (`core/project_file.py`): new project settings must be added to `document()` and `_project()` there (Configurables round-trip through `values()` / `from_values()`). Views that hold a project settings object rebind on `Session.project_replaced`.
- Choreographies (`core/animation/`) declare their `phase` (build, show or clear; ids unique across phases) and keep its boundaries (`phases.py`): a build ends exactly at `TileFrame.final`, a show starts and ends at it, a clear starts at it (and should end with nothing left, for loops). `test_every_choreography_keeps_its_phase_boundaries` checks every registered one; new show effects go in `show.py`. Chains (`plan_chain`): a build that plans only from its scene sets `fits_any_layout` (it can then lead in, landing on a laid-out scene: break stacking ties with `scene.levels`, never array order, and end on `TileFrame.final(scene)`); one whose first frame lies still on the table sets `rests_on_table` (it can be led into). `test_a_lead_in_lands_exactly_where_the_next_build_starts` checks every pair. Builds that order their tiles declare `order`, `sweep`, `sweep_angle` and `spread` with `orders.py`'s functions, so a new order goes in `ORDERS` once (and in `RANDOM_ORDERS` if it has no direction); directions come from `compass.py` (shared with Wave).
- Matching methods (`core/matching/method.py`) are registered like choreographies; the project keeps every method's settings (`match_methods`) and the chosen id. A method that shows no library photos sets `needs_library = False`. Results that show the picture itself (`MatchResult.picture`, the Jigsaw Puzzle) are drawn by sampling the picture at each piece's home footprint (`scene.picture_uv`, `PictureTextures`, `assembly.render_picture`), never from cut-out images. `test_every_method_fills_the_regions_and_round_trips` checks every registered method.
- Zoomed-in views sharpen tiles with `ui/render/zoom_detail.ZoomDetail` (the Matching tab): make the tile layer with `detail_pages`, and call `show()` whenever the layer or its instances are replaced (it redirects tiles in view to crops read at the screen's resolution and must see the usual instances first).
- `TileLibrary` defines `__len__`, so an empty library is falsy: compare with `is None`.
